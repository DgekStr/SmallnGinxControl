# Roadmap — 2026-10-04

## Readiness v1.0

- Основные сценарии управления nginx: **100%** — hosts, reverse proxy, edit, logs, reload и maintenance toggle реализованы.
- Multi-server и SSH trust: **100%** — изоляция профилей и fingerprint pinning реализованы и покрыты тестами.
- Проверки приложения: **100%** — unit/backend и browser E2E проходят на релизном checkout.
- Production deployment: **95%** — systemd и HTTPS проверены; сквозное изменение действующего vhost в production намеренно не выполнялось.
- Release и clone-based установка: **100%** — README, HTML, installer, release notes, screenshots, tag и GitHub release подготовлены.
- Security hardening: **75%** — loopback upstream, HTTPS, CSRF/secure cookies и пароли настроены; MFA, helper вместо root и централизованный контроль сетевого доступа остаются отдельными работами.

**Итоговая оценка готовности v1.0: 93%.** Проценты — оценка выполнения вех, не гарантия безопасности или SLA. Основные остаточные риски перечислены в release notes.

## Следующие этапы

### v1.1 — безопасные операционные практики

- Проверка maintenance toggle на отдельном тестовом домене с реальным откатом.
- Ограниченный privileged helper для операций nginx вместо запуска всего web-процесса от root.
- MFA или интеграция с внешним identity provider; аудит ротации и срока хранения событий.
- Автоматизированный backup/restore drill для DB, `SECRET_KEY` и конфигураций.

### v1.2 — эксплуатация нескольких серверов

- Экспорт и импорт профилей без раскрытия secret material.
- Очередь и лимиты параллельных SSH-операций, видимый health и свежесть метрик.
- Проверка сертификатов и срока действия для всех TLS vhost.
- Проверка CI на поддерживаемых версиях Ubuntu и Python.

### Backlog

- Политики доступа по ролям и разделение read-only/admin.
- Защищённое удалённое хранилище резервных копий и retention policy.
- Оповещения о недоступности серверов, истечении TLS и неуспешном reload.
