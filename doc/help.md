# Руководство SmallnGinxControl

SmallnGinxControl — self-hosted панель для локального и SSH-управления nginx. Интерфейс и API работают на Django/Waitress; Docker и Node.js production-серверу не нужны.

## Доступ

### Демо

Для локальной проверки запустите `serve.py` по инструкции быстрого старта в [README](../README.md). Demo использует `admin / 12345`, слушает `127.0.0.1:7444` по HTTP, показывает синтетические данные и не выполняет системные nginx-команды.

Не публикуйте demo в LAN: привязка demo к `0.0.0.0` блокируется намеренно. Для просмотра с другого компьютера используйте туннель:

```sh
ssh -N -L 7444:127.0.0.1:7444 USER@SERVER_IP
```

Затем откройте `http://127.0.0.1:7444`.

### Production

Установщик настраивает nginx принимать HTTPS на `0.0.0.0:7444`, а Waitress оставляет на loopback `127.0.0.1:7445`. `0.0.0.0` — адрес привязки сервера, не адрес для браузера. Подключайтесь по IP/DNS машины, например `https://192.168.0.43:7444`; не открывайте `https://0.0.0.0:7444` и не публикуйте backend-порт `7445`.

Разрешайте TCP/7444 только доверенным сетям в firewall: установщик firewall не меняет. Для SSH-туннеля к production используйте `ssh -N -L 7444:127.0.0.1:7444 USER@SERVER_IP`, затем откройте `https://localhost:7444`.

Установщик создаёт self-signed сертификат с SAN для настроенного IP/DNS и `localhost`. При первом соединении браузер предупреждает, что сертификат не удостоверен публичным центром сертификации. Для первоначального входа подтвердите исключение браузера или установите сертификат из доверенного канала. После входа скачайте публичный сертификат в `Настройки → HTTPS панели` и добавьте его в доверенные сертификаты клиентского устройства. Приватный ключ не скачивается и хранится на сервере с правами `0600`. Его перевыпуск заменяет сертификат, поэтому клиентам нужно заново доверить новую публичную часть.

В разделе `Настройки → HTTPS панели` можно перевыпустить self-signed сертификат или заменить его PEM-парой certificate/private key. Загружаемые файлы должны быть не больше 200 КБ каждый; ключ должен соответствовать сертификату, быть незашифрованным и включать SAN для адреса панели. Перед применением выполняются `nginx -t` и reload; при ошибке предыдущая конфигурация и файлы восстанавливаются.

Для сертификата без браузерного предупреждения загрузите в настройках пару от доверенного CA, содержащую правильный SAN. Отдельно для host/reverse proxy доступны Let's Encrypt через Certbot: публичный DNS, email и входящий TCP/80 нужны только для этого сценария.

## Срок регистрации домена

Для каждого публичного домена у host/reverse proxy панель получает дату окончания регистрации через WHOIS и показывает остаток рядом со ссылкой домена. Проверки выполняются в фоне, результат кэшируется на сутки; при выборе нового SSH-профиля его домены проверяются сразу. Нужен исходящий TCP/43 к WHOIS-серверу соответствующей зоны; если реестр недоступен или не публикует expiration date, UI покажет «Срок неизвестен».

Поддомены, включая `*.dgek.ru`, сводятся по Public Suffix List к регистрируемому корню (`dgek.ru`). IP-адреса, `.onion`, localhost и локальные/служебные имена не проверяются. Цвет предупреждения: жёлтый менее чем за 30 дней, розовый менее чем за 20, красный менее чем за 10. Во время фоновой проверки отображается нейтральное «Проверяется…».

В `Настройки → Уведомления Mattermost` сохраните Incoming Webhook URL и нажмите `Проверить`, чтобы отправить тестовое сообщение. URL хранится зашифрованным и не показывается при повторном открытии настроек. В `Настройки → Проверка доменов` включите scheduler, задайте интервал 1–365 дней и время уведомления по часовому поясу сервера. При первом запуске панель проверяет домены всех доступных local/SSH-профилей; Mattermost получает список доменов с остатком менее 10 дней. Повторное предупреждение по домену отправляется не чаще раза в 24 часа. Нужен исходящий доступ к WHOIS TCP/43 и Mattermost HTTP(S) webhook. Demo-режим не отправляет сообщения и не запускает scheduler.

## Возможности

- Управление виртуальными хостами и reverse proxy; поиск и фильтры по домену, пути, upstream и состоянию.
- В строке HTTPS нажмите значок замка, чтобы открыть subject, issuer, серийный номер, срок действия в UTC, путь к сертификату и остаток дней. Показывается сертификат из `ssl_certificate`; если файл недоступен или не читается, панель сообщит об этом.
- Включение/отключение стандартных конфигов nginx, редактор `nginx.conf` и файлов хостов, проверка `nginx -t`, reload и подтверждаемый restart.
- Maintenance для reverse proxy с сохранением оригинала и транзакционным восстановлением; статические хосты можно полностью выключать.
- Per-host access/error logs, retention и TOP-5 трафика.
- Метрики uptime, CPU, RAM, сети и заполнения root-раздела.
- Несколько профилей nginx: demo, local и SSH. SSH поддерживает пароль, приватный ключ и агент, проверку host key fingerprint и зашифрованное хранение сохранённого секрета.
- TOTP 2FA, смена пароля, ограничение попыток входа и настраиваемая длительность сессии.
- Аудит успешных и ошибочных операций.

## Подключение серверов

Откройте `Серверы → Добавить сервер`, укажите имя, IP/DNS, SSH-порт, пользователя и способ авторизации. Приватный ключ выбирается на машине, где работает панель, а не на nginx-сервере. Пароль и пароль ключа вводите только в интерфейсе.

Получите SHA256 fingerprint SSH host key кнопкой рядом с полем, сверьте его по доверенному каналу и только после этого подтвердите ключ. Получение fingerprint само по себе не удостоверяет сервер. При последующем несовпадении закреплённого ключа соединение блокируется.

Удалённому Ubuntu-серверу нужны Python 3.10+, `/usr/sbin/nginx`, `/usr/bin/systemctl`, права на конфиги/журналы и reload/restart. Постоянный агент и отдельные Python-пакеты на управляемом сервере не устанавливаются. Ошибка одного профиля не подменяется данными другого; одновременно работают до четырёх метрик-сборщиков.

Удаление подключения не удаляет nginx-конфиги и резервные копии. Для восстановления сохранённых SSH-секретов необходимы база панели и прежний Django `SECRET_KEY`. Смена назначения профиля очищает его старые метрики.

## Конфигурации nginx

Единица управления — файл, а не отдельный `server`-блок. Если в файле несколько сайтов, операции затрагивают все его блоки. Файлы с `proxy_pass`, `fastcgi_pass`, `grpc_pass`, `uwsgi_pass` или `scgi_pass` относятся к reverse proxy.

Linux inventory следует графу `include` из `nginx.conf`. Внешние файлы за `SNC_NGINX_ROOT` видны как предупреждения, но не редактируются. Нестандартные include нужно переключать через `nginx.conf` вручную. Конфигурация control-plane скрыта из списка обычных хостов и защищена от редактирования, отключения и удаления через UI.

Перед production-операциями изучите nginx-конфиги и их include. Не редактируйте один файл параллельно через панель, shell, Certbot и другие средства. Управляемые операции создают backup, сериализуются lock-файлом и откатываются при неуспешной проверке/reload.

### Maintenance

При отключении стандартного reverse proxy nginx-vhost остаётся включённым и возвращает HTTP `503` с `/var/www/html/maitenance.html`; оригинальная конфигурация сохраняется вне nginx root в state. При включении она восстанавливается байт-в-байт. Конфиг хоста и symlink удаляются транзакционно, с `nginx -t`, reload и rollback.

## Логи и трафик

Логи читаются из `SNC_LOG_ROOT` и дополнительных разрешённых абсолютных путей `SNC_LOG_EXTRA_ROOTS` (по умолчанию `/var/http`). Динамические имена, syslog и пути вне этих корней не читаются. Просмотр ограничен последними 128 КиБ на файл.

В `Настройки → TOP-5 по трафику` задаётся размер выборки каждого access log: 1 байт–100 МБ, по умолчанию 128 КиБ. `$bytes_sent` — скачанные данные, `$request_length` — отправленные данные вместе с request line и headers. Это оценка по хвосту access log, а не lifetime-счётчик; `~` обозначает частичный sample, `—` — отсутствие upload-поля в формате журнала.

В `Настройки → Хранение логов` задаётся срок от 1 до 3650 дней. Ежедневный systemd timer ротирует и очищает только `*-data.log`, другие журналы nginx не изменяет.

## Метрики и безопасность

Пики CPU/сети измеряются раз в 5 секунд за последние 24 часа. Объёмы сети берутся из счётчиков ОС и могут обнулиться после перезапуска интерфейса/ОС. Для точной LAN-метрики укажите физический интерфейс в `SNC_INTERFACE`.

Панель предназначена для доверенного администратора: запуск с root-правами и произвольное редактирование nginx-конфигураций эквивалентны root-доступу к серверу. Не открывайте сервис в публичный интернет без HTTPS, сильного пароля и сетевого ограничения; предпочитайте доступ только из LAN либо SSH-туннель.

## Проверки

```powershell
.\.venv\Scripts\python.exe manage.py test panel
.\.venv\Scripts\python.exe manage.py check
node --check static/app.js
npm ci
npm run assets
npm run test:e2e
```

В Windows Playwright использует установленный Google Chrome; браузер можно выбрать через `SNC_TEST_BROWSER`. В Linux перед E2E установите `npx playwright install chromium`. Тесты используют отдельную демосреду и не меняют рабочие production-конфиги.
